# 공지사항 페이지 (Notice Page) 구현 계획

## 1. 개요

- **목적**: 시스템 공지사항 및 자체 진행 이벤트 소식을 유저에게 전달.
- **특징**: 스크롤 피드 방식이 아닌 전통적인 페이지네이션(Pagination) 구조 채택을 통해 원하는 정보를 정확하게 탐색.

## 2. 레이아웃 및 컴포넌트

- **Notice List View**:
  - **검색창 (`SearchBar`)**: 제목 및 내용 기반 필터링.
  - **목록 (`NoticeList`)**:
    - `NoticeItem` 단위 렌더링.
    - 게시글 종류 뱃지 (공지사항 / 이벤트 색상 분리).
    - 글 제목, 등록일 표기.
  - **페이지네이션 바 (`Pagination`)**: 1, 2, 3... 형태의 페이지 이동 컨트롤.
- **Notice Detail View**:
  - 상단 메타데이터 헤더: 뱃지(분류), 제목, 작성자(관리자), 등록일.
  - 본문 영역: 리치 텍스트 에디터로 작성된 HTML 콘텐츠 렌더링 영역 (보안상 `DOMPurify` 등 활용 권장).

## 3. 상태 관리

- **Local State**: 현재 머무르고 있는 페이지 번호 (`currentPage`), 검색창 입력 텍스트.
- **Server State**:
  - 특정 페이지의 게시글 목록 (목록과 함께 Total Pages 데이터 필요).
  - 단일 게시글의 상세 콘텐츠.

## 4. API 연동

- `GET /api/posts?category={Notice|Event}&page={pageNumber}&search={query}` (목록 데이터 로드)
- `GET /api/posts/{id}` (게시글 상세 로드)

## 5. 주요 인터랙션

- 검색창 입력 시 리스트 및 페이지네이션 데이터 초기화 후 새롭게 페칭.
- 아이템 클릭 시 상세 뷰(또는 `/notice/{id}`)로 이동.
- (향후 확장 고려 사항) 관리자 계정 식별 시 화면 하단이나 상단에 '글쓰기' Floating 버튼 렌더링 처리.
